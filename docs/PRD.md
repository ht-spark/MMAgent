# MMAgent 产品需求文档（PRD）

版本：V 1.1.0

---

## 1. 背景与目标

### 1.1 背景

数学建模竞赛（如 MCM/ICM、全国大学生数学建模竞赛等）的完整流程——读题、拆解、查文献、选方法、写代码、验证结果、撰写报告——通常需要 3-4 天，对参赛者的综合能力要求极高。现有工具要么只能做单一环节（如代码执行、文献检索），要么依赖固定的建模模板，缺乏端到端的自动化能力。

MMAgent 的目标是：**把"读懂题目 → 拆解子问题 → 建模 → 跑数据得结果 → 验证 → 写成报告"这一复杂人工流程，自动化为一个可监控、可干预、可复现的系统。**

### 1.2 目标

- 让用户提交一道数学建模题（可附数据），系统自动产出完整建模报告（Markdown/DOCX），包含图表、表格、中间代码与数据。
- 提供知识库 RAG 辅助，帮助用户在建模前期梳理思路、检验方法。
- 建立"越用越聪明"的知识闭环：任务产出回灌知识库，知识库引导后续任务。

### 1.3 成功标准

| 指标         | 目标                                        |
| ------------ | ------------------------------------------- |
| 任务完成率   | ≥ 80% 的提交任务产出完整报告               |
| 用户满意度   | 平均 ≥ 4/5（5 分制）                       |
| 平均耗时     | 从提交到产出报告 ≤ 30 分钟（复杂题可放宽） |
| 知识库使用率 | ≥ 50% 的用户在建模前使用过头脑风暴功能     |

## 2. 用户与场景

### 2.1 目标用户

| 用户类型           | 典型画像                 | 核心诉求                            |
| ------------------ | ------------------------ | ----------------------------------- |
| 数学建模竞赛参赛者 | 大学生，备赛期间时间紧张 | 快速获得完整建模报告，辅助参考      |
| 数学建模教练/导师  | 高校教师，指导学生参赛   | 批量评估学生思路，检查方法合理性    |
| 科研人员/工程师    | 需要快速验证建模思路     | 用 RAG 辅助文献调研，用智能体跑原型 |

### 2.2 核心场景

**场景 A：直接求解（路径 A）**
用户提交题目 → 系统自动拆解 → 逐问求解 → 产出报告。适用于时间紧迫、需要快速获得参考方案的场景。

**场景 B：思路先行（路径 B）**
用户上传参考资料 → 分块嵌入 → 头脑风暴提问打磨思路 → 将思路体现在题面/数据中 → 提交建模任务。适用于需要先调研再求解的场景。

**场景 C：迭代改进（路径 C）**
跑一次任务 → 阅读报告与审查意见 → 在知识库补充文献 → 再次提交，逐步逼近更优解。适用于对结果质量要求高的场景。

## 3. 功能需求

### 3.1 建模任务（智能体求解）

#### 3.1.1 提交任务

- **FR-001**：用户可提交题目文本，或上传 `.md`/`.txt` 题目文件。
- **FR-002**：用户可附加数据文件（CSV/Excel/图片等，可多个）。
- **FR-003**：用户可选择/配置大模型（OpenAI、DeepSeek 或自定义 OpenAI 兼容 endpoint）。
- **FR-004**：提交后任务进入异步执行队列，返回任务 ID。

#### 3.1.2 运行中的人工介入

- **FR-005**：若题目信息不足（G0 摄入门），系统弹出澄清请求，用户可终止或补充材料。
- **FR-006**：每个子问题可弹出预算确认（沿用默认或覆盖上限），用户可调整每问的预算。
- **FR-007**：用户可随时取消任务，系统停止后续执行并保留已产出的中间产物。

#### 3.1.3 进度与产物

- **FR-008**：系统通过 SSE 实时推送节点级进度（Phase 1 → Phase 6）。
- **FR-009**：任务完成后，用户可获取完整产物包：
  - 建模报告（Markdown / DOCX）
  - 图表（14 类学术图）
  - 表格（含 LaTeX 公式）
  - 中间代码与数据
  - 审查报告

#### 3.1.4 关键能力

- **FR-010**：自动方法探索——联网检索相关建模方法 + LLM 思考双路径，避免"拍脑袋选型"。
- **FR-011**：代码化求解——LLM 生成 Python 求解代码并在隔离子进程执行，结果可复现。
- **FR-012**：按题型校验——评价/预测/优化/随机/分类/聚类/仿真等问题分别有对应的验证规则。
- **FR-013**：可追溯报告——报告章节与证据、决策日志、各问结论一一对应。

---

### 3.2 知识库与头脑风暴（RAG 辅助）

#### 3.2.1 文档管理

- **FR-014**：用户可上传 PDF/DOC/DOCX/PPT/PPTX/PNG/JPG/Markdown/TXT 文件，或含上述文件的 ZIP 包。
- **FR-015**：非 Markdown 文档经 MinerU 自动转换为 Markdown（公式、表格可识别）。
- **FR-016**：用户可删除文档，系统同步删除向量并重建索引。
- **FR-017**：用户可查看已索引文档清单与切片数量。

#### 3.2.2 检索与问答

- **FR-018**：用户可在知识库中进行头脑风暴提问，获得带引用出处的回答。
- **FR-019**：检索采用混合检索（稠密 BGE 语义向量 + 稀疏 BM25 关键词）+ RRF 融合，各取 Top 5 片段。
- **FR-020**：每个回答附带 `source_file`（来源文档）与原文片段，便于用户核对。
- **FR-021**：可选 LLM 上下文压缩，去除冗余噪声。

#### 3.2.3 历史与统计

- **FR-022**：用户可查看历史头脑风暴讨论。
- **FR-023**：用户可查看知识库统计（文档数、切片数、索引状态）。

---

### 3.3 两功能的协同（设计目标）

- **FR-024**（规划中）：将知识库中的建模思路直接加载进任务智能体，引导其建模。
- **FR-025**（规划中）：将每次任务产出的报告回灌知识库，形成"越用越聪明"的闭环。

## 4. 非功能需求

### 4.1 性能

- **NFR-001**：任务提交到首次 SSE 连接 ≤ 2 秒。
- **NFR-002**：单个子问题求解（含代码执行）≤ 10 分钟（复杂题可放宽）。
- **NFR-003**：知识库检索响应 ≤ 3 秒。

### 4.2 可靠性

- **NFR-004**：代码执行在隔离子进程中运行，拒绝 NaN/Inf，防止污染主进程。
- **NFR-005**：支持断点续跑（检查点机制），任务中断后可从上次节点恢复。
- **NFR-006**：LLM 调用失败时有降级策略（联网失败 → LLM 思考兜底；代码失败 → 重试 → 阻塞）。

### 4.3 安全

- **NFR-007**：文件路径解析拒绝目录穿越。
- **NFR-008**：上传大小限制（单文件 ≤ 200MB，压缩包 ≤ 500MB / 500 文件）。
- **NFR-009**：API Key 等敏感配置持久化于 `api_settings.json`，不硬编码。

### 4.4 可观测性

- **NFR-010**：结构化日志（`run.log` JSON），记录各节点耗时、token 消耗、工具调用。
- **NFR-011**：检查点（`artifacts/_checkpoints/<run_id>/`），支持断点续跑与问题排查。

## 5. 上线与迭代

### 5.1 当前版本（V1.0）范围

**已实现**：

- 建模任务端到端流程（Phase 1-6）
- 三道质量门（G0/GQ/GF）与预算控制
- 知识库上传、转换、分块、嵌入、检索
- 头脑风暴问答与引用溯源
- FastAPI 后端 + React 前端
- SSE 实时进度推送

**暂未实现（规划中）**：

- 知识库与建模任务的深度集成（思路加载 / 报告回灌）
- 多轮对话式建模（用户与智能体 iterative 交互）
- 团队协作功能（共享任务、评论、审批流）

### 5.2 迭代路线

| 版本 | 目标                                            |
| ---- | ----------------------------------------------- |
| V1.1 | 修复已知 bug，优化 prompts，提升报告质量        |
| V1.2 | 打通知识库 ↔ 建模任务双向桥接                  |
| V2.0 | 多轮交互式建模，支持用户与智能体 iterative 修订 |
| V3.0 | 团队协作，支持多人共享任务与审批流              |

## 6. 附录

### 6.1 术语表

| 术语          | 说明                                                       |
| ------------- | ---------------------------------------------------------- |
| LLM-only 策略 | 不预设固定建模方法论，由 LLM 围绕具体问题驱动全流程        |
| G0/GQ/GF      | 三道质量门：G0 摄入门、GQ 逐问门、GF 交付门                |
| RAG           | Retrieval-Augmented Generation，检索增强生成               |
| RRF           | Reciprocal Rank Fusion，倒数排名融合，用于多路检索结果融合 |
| SSE           | Server-Sent Events，服务端推送事件，用于实时进度           |
| Pydantic      | Python 数据验证库，用于定义数据结构                        |
| LangGraph     | 基于 LangChain 的状态图编排框架                            |
