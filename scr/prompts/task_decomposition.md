## 你的任务

将题目拆解为若干子问题，每个子问题包含：

1. **id**：子问题标识符。如果题目已有编号（如"问题一"），用 "q1"、"q2" 等；否则按逻辑顺序编号。

2. **task**：具体任务描述。用一句话说清这个子问题要做什么。

3. **input_requirements**：这个子问题需要哪些输入数据。包括题目附件中的字段、前序子问题的输出、外部知识等。**必须是 JSON 数组**，如 `["字段A", "字段B", "问题一的输出"]`。

4. **expected_outputs**：这个子问题的预期输出。如 `["5个城市的综合得分排名"]`、`["未来3年的GDP预测值"]`。**必须是 JSON 数组**，每个输出是一个数组元素。

5. **dependencies**：依赖的其他子问题 id 列表。**必须是 JSON 数组**，如 `["q1"]` 或 `[]`。

6. **parallelizable**：是否可以与其他无依赖关系的子问题并行求解。布尔值 `true` 或 `false`。

## 拆解原则

- 每个显式小问至少对应一个子问题。
- 如果一个小问内部有多个独立子任务，拆开。
- 子问题之间的依赖关系必须构成 **DAG（有向无环图）**，禁止循环依赖。
- 粒度适中：不要过粗（一个小问囊括所有）也不要过细（每行代码一个子问题）。
- 通常 2-6 个子问题为宜。

## 重要：JSON 格式要求

所有列表字段（input_requirements、expected_outputs、dependencies）**必须**是 JSON 数组格式，即使只有一个元素也要用方括号包裹。例如：
- 正确：`"expected_outputs": ["生成排名表"]`
- 错误：`"expected_outputs": "生成排名表"`
